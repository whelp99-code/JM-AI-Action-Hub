# 모바일 UX 및 화면설계

## 설계 목표

- 스마트폰 한 손 사용
- 입력 직후 구조화 결과 확인
- 등록 대상이 항상 보임
- 위험 항목은 노란색 검토 표시
- 승인과 실행을 분리
- 기존 앱으로 이동할 수 있는 결과 링크

## 화면 1 — 빠른 등록

```text
┌─────────────────────────────┐
│ JM-AI Action Hub       ●    │
├─────────────────────────────┤
│ 빠른등록  오늘  최근  설정 │
├─────────────────────────────┤
│ 말하거나 붙여넣으세요       │
│ ┌─────────────────────────┐ │
│ │ 내일 10시 고객 미팅... │ │
│ └─────────────────────────┘ │
│ [붙여넣기] [음성] [지우기] │
│ [출처 ▼] [실행 항목 만들기]│
└─────────────────────────────┘
```

행동:

- 붙여넣기: Clipboard API, 실패 시 입력창 포커스
- 음성: Web Speech API, 미지원 시 iPhone 키보드 받아쓰기 안내
- 공유: PWA Web Share Target 지원 브라우저에서 원문 수신

## 화면 2 — 생성 항목 검토

```text
┌ 일정 → ICS 일정   검토 필요 ┐
│ ☑ 선진 HCI 미팅              │
│ 유형 [일정] 목적지 [ICS]     │
│ 시작 [2026-07-29 10:00]      │
│ 제목/설명/프로젝트 수정      │
│ 신뢰도 86%        [수정 저장]│
└───────────────────────────────┘

[선택 제외] [선택 승인] [승인 항목 실행]
```

원칙:

- 체크박스는 이번 행동의 대상만 선택
- `검토 필요`는 수정 후 저장하면 해제 가능
- 사용자가 원하면 강제 승인할 수 있지만 명시적 체크가 필요
- 외부 앱 호출은 실행 버튼 이후

## 화면 3 — 오늘

그룹:

- 가용시간·보호 Buffer·계획량·초과량
- 오늘 일정·오늘 마감·지연 업무
- Top 업무와 연기 후보
- AI 위임 후보
- 만료 Follow-up과 응답 대기
- 검토 필요와 Sync Conflict

Todoist와 GitHub는 Signed Webhook과 Reconciliation으로 최신 상태를 회수한다. Calendar는 등록 결과와 주기적 대조를 사용한다. Today 화면은 새로운 업무 원장이 아니라 외부 원장 상태를 바탕으로 판단을 제공하며, 상세 편집은 원래 앱 링크에서 수행한다.

## 화면 4 — 최근

- 원문 앞 90자
- 생성 항목 수
- 계획 상태
- 생성 시각
- 누르면 빠른 등록 화면에서 계획 재열기

## 화면 5 — 설정

- API 키를 브라우저 localStorage에 저장
- Connector별 configured·healthy·detail 표시
- Worker route와 실행 가능 상태 표시
- execution mode, parser mode, worker inline 표시
- Control loop 1회 실행과 상태 새로고침
- 실제 Provider Token·Webhook Secret은 UI에 표시하거나 저장하지 않음

## iPhone 사용 흐름

### 홈 화면 설치

1. Safari에서 Action Hub HTTPS 주소 열기
2. 공유 버튼
3. 홈 화면에 추가
4. 생성된 Action Hub 아이콘 실행

### 카카오톡에서 입력

MVP 기본:

1. 메시지를 길게 눌러 복사
2. Action Hub 홈 화면 아이콘
3. 붙여넣기
4. 실행 항목 만들기

단축어 확장:

1. 카카오톡에서 텍스트 공유 또는 복사
2. Action Hub 단축어 실행
3. PWA 열기 또는 API에 직접 전송

### 음성

Safari의 Web Speech 지원이 일정하지 않으므로, 가장 안정적인 iPhone 방식은 입력창을 누른 후 키보드 마이크로 받아쓰기다. 앱 내 음성 버튼은 지원 브라우저에서 추가 편의 기능으로 사용한다.

## 접근성

- 버튼과 입력에 명시적 label
- 상태는 색상뿐 아니라 텍스트로 표시
- 최소 터치 높이 약 44px
- 시스템 글꼴 사용
- 작은 화면에서 단일 열로 전환
